# Oneshot report - Shardfront (claude-fable-5.2-high)

## Summary

Shardfront is a playable browser RTS vertical slice: two asymmetric factions (15 units, 12 structures) fight
on one procedurally authored 1v1 map with a worker economy, base building, tech, fog of war, three AI
difficulties, a guided tutorial, replays and a post-game summary. It is built on a deterministic 20 Hz
TypeScript simulation that runs headless (tests, benchmark, balance tool) and is rendered with Three.js
instancing under a React HUD. All art, effects and audio are generated by code; nothing external is shipped.

## Architecture

Stack: TypeScript (strict), Vite, Three.js (WebGL 2 `WebGLRenderer`), React 19 for menus/HUD, Vitest,
playwright-core for the browser smoke/screenshot script. One package with folder modules instead of a
multi-package monorepo, to keep `npm ci` and the static build simple; a test enforces that `sim`, `data`,
`nav`, `world`, `net` and `ai` never import rendering/UI/audio or touch DOM, wall-clock or `Math.random`.

- `src/sim` - fixed-tick simulation. Integer entity ids, structure-of-arrays typed buffers for hot state,
  seeded RNG, command validation (`applyCommand`), orders (move, attack-move, patrol, attack, follow, gather,
  build, construct/repair, ability), steering + separation + wall sliding, combat with delayed deterministic
  hits, production, vision grid with ray tables, objectives, statistics, FNV state hash, `FixedClock`.
- `src/data` - balance tables and schema validation. `src/world` - map generator. `src/nav` - A* + string pulling
  with a per-tick path budget and shared group corridors.
- `src/ai` - `AIController` (census, perception with decaying memory, economy, construction with site
  reservation, composition weights, scouting, army modes). It calls the same `applyCommand` as a player.
- `src/net` - command envelopes, replay format, label sanitising, fog-filtered snapshots.
- `src/game` - `GameSession`: local authoritative loop, input delay, replay record/verify, alerts, HUD read
  model, tutorial director. `src/render` - instanced entity meshes with a patched standard material (team mask,
  emissive mask, gait, construction clip, dissolve, fog of war), terrain, GPU particles, decals, 2D overlay.
- `src/input`, `src/audio`, `src/ui`, `src/persistence`, `src/app` - as named.

## Assumptions and deviations

- **Single package, not a monorepo**; folder modules with a tested import boundary.
- **WebGL 2 only** (no WebGPU adapter); pathfinding runs synchronously inside the simulation with a per-tick
  budget instead of in Web Workers, so results stay deterministic; no flow fields (shared group path +
  formation offsets + local separation instead).
- **Floats, not fixed point**: positions are quantised to 1/1024 each tick and the simulation avoids
  trigonometric functions; hashes match within one runtime, cross-engine determinism is not claimed.
- **Terrain is pre-revealed**: both players know the map layout; fog hides units, structures and their changes.
- **Key conflict**: the brief binds WASD to both camera and commands. WASD pans only while nothing is selected;
  arrows, middle-drag, minimap and optional edge scroll always pan. Structure slots use Q W E T D Z so R can
  stay "rally".
- **Extra stalemate rule**: besides the 18-minute rule, a match still running at 35:00 is decided by surviving
  force value (announced at 30:00). AI mirror matches could otherwise mine out and stall forever.
- **Economy numbers** (5 ore / 4 flux per trip) were tuned so AI matches last about 8-20 minutes.
- **Chorus has eight units** as listed in the brief (the brief's "14 units" count is off by one).
- **Sensor Spike** is visible to enemies who have vision of it but cannot be destroyed or detected specially.
- Workers do not auto-harvest at match start (the brief's loop asks the player to assign them); workers trained
  later do.
- Resource amounts in fogged areas are read live (a depleted seam disappears under fog).
- A debug hook `window.__sf` (advance, autopilot, camera) ships in the build for automation.
- No ESLint configuration, service worker, or Playwright test inside `npm test` (the browser flow is
  `npm run screenshot`).

## Known issues and limitations

- Balance is only tuned by AI-vs-AI runs: Helix won 5 of 8 cross-faction Normal matches; Bulwark lines are
  strong against Chorus early.
- Unit models are simple primitive assemblies; animation is procedural (leg swing, bob, recoil, squash), with
  no bespoke hit/ability animations, LODs or portraits beyond rendered icons.
- Units can bunch up and "crowd-arrive" a few units short of a point in tight spaces; large units may clip
  cliff corners visually; melee surrounds are approximate.
- Group moves share one path; there is no formation ordering by speed, and no kiting micro for the AI.
- Ghosted (last-known) structures have no timestamp label and cannot be selected.
- Placement preview does not show a firing cone, slope or path-blockage explanation beyond valid/invalid text.
- Ctrl+number control groups can be intercepted by the browser (use Alt+number or fullscreen).
- The JS bundle is one 1 MB chunk (290 kB gzip); there is no progressive asset loading because there are no
  assets to stream.
- Replays only verify within the same build/runtime; AI autopilot (debug) commands are not recorded.
- No sandbox mode, observers, networking, cloud saves, campaign or additional maps.

## Self-assessment

- **Playability: 7/10** - the full RTS loop works for both factions against three AI levels with a tutorial and
  replays, but no human has played it, so pacing, pathing feel and balance are only machine-checked.
- **Visual polish: 6/10** - coherent stylised look with readable team colours, fog, glow, effects and a clean
  HUD, but models are primitive-built, the ground is plain and animation is minimal.
- **Brief fidelity: 6/10** - most systems of the brief exist in real, tested form on the requested
  architecture, while WebGPU, workers, flow fields, a few abilities, networking and several production-scale
  asset/performance requirements are absent or simplified.
